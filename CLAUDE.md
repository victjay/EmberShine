## CRITICAL — Never Change
- Next.js 16 uses `src/proxy.ts` with `export default async function proxy()`.
  This is the correct convention for Next.js 16.
  Do NOT use `middleware.ts` — it is deprecated in Next.js 16. Never change this.

- `src/proxy.ts` handles locale redirect. Rules (in order):
  1. Already `/ko/...` or `/en/...` → pass through
  2. `/private/...` → pass through (no locale prefix)
  3. `/api/...` → pass through
  4. `/login` → pass through (no locale prefix, single path)
  5. `/_next/...`, static files (`.ico`, `.png`, `.svg`, etc.) → pass through
  6. `/robots.txt`, `/sitemap.xml`, `/manifest.webmanifest` → pass through
  7. All other paths → redirect to `/ko/{path}` (defaultLocale)
  NEVER remove or reorder these rules.

- `app/[lang]/layout.tsx` is the root layout for all public pages.
  NEVER add `<html>` or `<body>` to any public page component.
  NEVER call `createClient()` or `getUser()` in public page components.

- `app/private/layout.tsx` and `app/login/layout.tsx` are independent root layouts.
  Each must include `<html>` and `<body>`.
  Navigation between public ↔ private/login causes full page reload — this is NORMAL.

## Content Architecture

### Public content (blog, stories, portfolio): file-based
- Path: `content/{section}/{postId}.md`
- postId format: `{YYYY-MM-DD}-{slug}`  e.g. `2026-03-16-my-post`
- postId = filename stem = URL slug = edit identifier (세 가지 통일)
- postId is IMMUTABLE after creation — title changes do NOT rename the file
- On edit: update frontmatter only, add `updatedAt` field
- YAML serialization: always use `matter.stringify()` from gray-matter
  NEVER build frontmatter with template strings

### EN Translation files
- Path: `content/{section}/{postId}.en.md`
- Auto-generated by Gemini API when a post is saved
- Complete EN document (same frontmatter schema as KO, with locale: 'en' added)
- NEVER include `title_en` or `body_en` in frontmatter — translation is a full document
- Additional frontmatter fields: `locale: 'en'`, `translation_source: 'gemini'`
- `getAllPosts()` MUST exclude `.en.md` files from listing
  → filter: `filename.endsWith('.en.md')` (never use `slug.includes('.en')`)
- `getPostBySlug(section, slug, 'en')`:
  → tries `{slug}.en.md` first
  → falls back to `{slug}.md` if not found (sets `hasTranslation: false`)
- On update: existing `.en.md` is deleted first, then re-translated
  → if re-translation fails, `.en.md` is absent → EN page shows KO fallback with badge

### Private content (diary, inbox): Supabase only — zero Git involvement

## i18n Architecture

### Locales
- Supported: `['ko', 'en']`
- Default: `'ko'`
- Types and utils: `src/lib/i18n/locale.ts`
  → `isValidLocale(value)` — takes `unknown`, returns `value is Locale`
  → NEVER use `defaultLocale` as fallback for invalid locale → call `notFound()`

### UI Dictionary
- `messages/ko.ts`, `messages/en.ts` — static dictionaries
- `messages/index.ts` — `getDictionary(lang)` loader
  → MUST have `import 'server-only'` at top
  → NEVER import in Client Components

### Root Layout Structure
```
app/
  [lang]/layout.tsx     ← Public pages root layout (<html lang={locale}>)
  private/layout.tsx    ← Admin pages root layout (<html lang="ko">)
  login/layout.tsx      ← Login page root layout (<html lang="ko">)
  layout.tsx            ← DELETED (does not exist)
```

### generateStaticParams — top-down rule
- `app/[lang]/layout.tsx` generates `[{ lang: 'ko' }, { lang: 'en' }]` (lang only)
- `app/[lang]/{section}/[slug]/page.tsx` generates `{ slug }` only
- NEVER generate `{ lang, slug }` combinations in `[slug]/page.tsx`
- This is the top-down pattern — parent provides lang, child provides slug

### LangToggle behavior
- Uses `usePathname()` to extract current locale prefix
- On toggle: replaces `/ko/` ↔ `/en/` prefix in URL, then `router.push()`
- DISABLED on `/private/...` and `/login` paths

### Translation failure behavior
- KO post save: always succeeds regardless of translation result
- Translation failure: `.en.md` not created, EN page shows KO content + "원문 (한국어)" badge
- `needsFallbackBadge(post, locale)`: `src/lib/i18n/fallback.ts`
  → returns `true` when `locale === 'en' && post.hasTranslation !== true`

## Admin Auth Pattern

### Server Actions (actions.ts)
- Import `assertAdmin` from `@/lib/auth/admin.ts`
- Call `await assertAdmin()` as the very first line
- Compares `user.email === process.env.ADMIN_EMAIL`
- Redirects to `/login` if not authorized

### Client Components (SectionControls.tsx)
- Check `session?.user?.email === process.env.NEXT_PUBLIC_ADMIN_EMAIL`
- Return `null` if not admin (prevents flash on server render)

## Server Action Pattern

### Standard pattern
```ts
export async function myAction(formData: FormData) {
  await assertAdmin()                     // 1. auth — always first
  // validate → return { error } on fail  // 2. validate (return, NOT throw)
  try {
    await pushToGitHub(...)               // 3. side effect in try
  } catch (e) {
    return { error: e instanceof Error ? e.message : 'Unknown error' }
  }
  redirect('/private/inbox?saved=1')     // 4. redirect OUTSIDE try/catch
}
```

### Translation pattern (non-blocking)
```ts
// After KO pushToGitHub succeeds, before redirect():
// Translation block is SEPARATE from save block — never merge
try {
  const translation = await translatePost({ ... })
  if (translation.success) {
    await pushToGitHub({ path: `content/{section}/${postId}.en.md`, ... })
  } else {
    console.error('[translate] skipped:', translation.error)
  }
} catch (e) {
  console.error('[translate] failed (non-blocking):', e)
  // NEVER return { error } here — save already succeeded
}
redirect('/private/inbox?saved=1')  // always runs regardless of translation result
```

## Slug & PostId Rules
- `safeSlug(title)`: lowercase, keep 가-힣/a-z/0-9, `.` → remove (not hyphen),
  replace others with `-`, collapse consecutive `-`, trim leading/trailing `-`,
  return `'untitled'` if empty
  e.g. `'Next.js 배포 가이드'` → `'nextjs-배포-가이드'`
- `ensureUniquePostId(section, baseId)`: check GitHub for existing file,
  append `-2`, `-3`... if conflict, max 10 attempts
- Both utilities live in `src/lib/content/slug-utils.ts`

## Gemini / AI Rules
- SDK: `@google/genai` (NOT `@google/generative-ai` — legacy, do not use)
- Client init: `new GoogleGenAI({ apiKey: process.env.GOOGLE_GENERATIVE_AI_API_KEY })`
- Response access: `response.text` (property, NOT `response.text()` method)
- Structured output: always use BOTH `responseMimeType` AND `responseJsonSchema`
  Schema types: `'object'`, `'string'` string literals (NOT `Type.OBJECT`, `Type.STRING`)
- `src/lib/ai/translate.ts`: MUST have `import 'server-only'` at top
- Translation failures MUST return `{ success: false, error }` — NEVER throw
